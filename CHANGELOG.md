# Changelog

Record every change under **Unreleased**: what changed, why, files touched, how it was validated (unit, virtual, or physical), and known gaps. Move entries under a dated heading when the robot image or a release is cut.

## Unreleased

### Added: LIMA face, gender-neutral voice, typed check-ins, mentor activities, and staff web app (2026-11-15)

**Why:** adapt Gigi into LIMA, the LLC peer-mentor robot, per the design research. See `docs/LIMA_MENTOR.md`.

**What:**
- **Face:** new `lima` character (mint on deep plum, robot-like) generated by `tools/generate_lima_face.py`. It is the default for all activities via `DEFAULT_FACE` / `GIGI_FACE`. The face renderer no longer re-saves unchanged sprite slices on every start, which removes the Git churn.
- **Voice:** Piper TTS engine in `expression/speech.py`. Default voice `en_US-sam-medium` (open non-binary voice dataset). Speed and pitch settings in `core/voice_settings.py` (`data/settings/voice.json`) apply from the next sentence. Audio for non-default voices is cached separately in git-ignored `data/speech_cache/`. Falls back to Nix TTS when Piper is missing. New tools: `download_voices.py` and `voice_audition.py` (a listening page with median pitch). Optional `[voice]` extra (`piper-tts`, GPL-3.0).
- **Check-ins:** `src/gigi/mentor/` (store, check-in engine, safety triage, launcher, robot I/O) and the `activities/mentor/mentor_checkin.py` runner. Five check-in scripts plus editable content in `Assets/mentor/`. The robot explains what it keeps and asks for consent, handles skip/stop, remembers reviewed profile facts, and flags urgent, follow-up, and note conditions.
- **Typed input:** students can type or talk and switch mid-session, mute the robot's voice, and set speed. All from the web app.
- **Web app:** `gigi lima` / `gigi lima-user`. Student kiosk; mentor/staff/admin portal with login, CSRF protection, lockout after failed logins, role scoping, review that saves to the profile and deletes the transcript, 14-day retention purge, profile deletion, voice settings, accounts, and an audit log.
- **Integration:** daemon routes `mentor_checkin_<id>` and lists `available_mentor_checkins`; the virtual console lists LIMA check-ins; virtual captions follow the speed setting; `sync_to_robot.py` and `setup_orangepi.sh` install Piper and the voice and copy the new assets.
- Tests: `tests/test_lima_mentor.py` (30 tests), added to CI.

**Validation:**
- Unit: 107/107 pass on Windows, Python 3.12.
- Virtual end to end (virtual console + web app):
  - Typed first-meeting check-in with disclosure and consent; the speed change mid-session reached the robot; follow-up flag shown.
  - Staff review saved classes and hobbies and deleted the transcript (0 messages left).
  - Weekly check-in greeted the returning student with remembered hobbies and classes.
- Piper synthesis checked on Windows: about 0.04 seconds of compute per second of audio after warm-up; speed change took effect.
- LIMA face rendered through the real face engine.
- **Not tested on the Orange Pi**: Piper on aarch64, face on the 7-inch screen, microphone in Talk mode, and the setup/sync script changes.

**Known gaps:** urgent flags notify no one automatically; local passwords instead of IU SSO; no HTTPS; the kiosk trusts the typed name; safety triage is keyword-based; all resource, event, and crisis text is sample text; the daemon's system log may contain recognized speech.

### Fixed: "real TTS" virtual mode crashed without PyTorch (2026-11-15)

**Why:** choosing `Speech: real TTS` in the console crashed activities at start-up (`AttributeError: 'NoneType' object has no attribute 'hub'`) because Silero TTS on Windows needs PyTorch, which is not a project dependency.

**What:** `virtual/speech.py` `make_speech` falls back to captions when the real engine fails and sends a `notice` event, which the console shows as a ⚠ line. `docs/VIRTUAL_ROBOT.md` explains how to install PyTorch for real TTS.

**Validation:** unit (new test `test_real_tts_failure_falls_back_to_captions`).

### Added: virtual robot and Virtual Robot Console (2026-11-15)

**Why:** test activities and LIMA mentor conversations on a laptop before using the physical robot.

**What:**
- `GIGI_VIRTUAL=1` mode (`core/config.py`): forces `IS_ROBOT=false`, disables NPU paths, enables a virtual joint model.
- `src/gigi/virtual/`: `VirtualHearing` (typed input), `VirtualSpeech` (captions with timing; optional real TTS), `VirtualVision` (simulated room built on the real `Vision` class), `VirtualMovement` (real `Movement` trajectory code with a recording controller), face mirror, LLM routing with a Wizard-of-Oz fallback, and `sandbox_chat.py`.
- `core/robot.py` and `interaction/robot_interface.py` import the virtual classes when `GIGI_VIRTUAL` is set. Activities are unchanged.
- `gigi virtual` CLI command and console (`virtual/console/`): runs any activity, shows the transcript, mirrored face, and joints; lets the tester type the student's lines, edit the room, answer as the wizard, use LIMA scenario presets, and export a transcript. Motor calibration is excluded from the console.
- Docs: `docs/VIRTUAL_ROBOT.md`, `docs/TESTING_GUIDE.md`, README section, `CLAUDE.md`.
- Tests: `tests/test_virtual_robot.py` (19 tests), added to CI.

**Validation:** unit (76/76 tests pass on Windows, Python 3.12). Virtual end-to-end through the console API: the sandbox (greeting, typed reply, wizard reply, clean exit, face mirrored) and Math Quest (5 questions answered, gestures, joint stream) ran unchanged. Not tested on Linux CI or on the physical robot.

**Known gaps:** no speech-recognition errors, pronunciation scoring, or speaker ID in virtual mode; the face renderer still opens its own window and re-saves its sprite PNGs; the joint view shows commanded positions only.
